  One diagram cannot say who uses checkout, where card data goes, and where it
  runs. This page draws each of those separately: the context, the data flow,
  and the deployment.

  ## Where card data goes

  The part of checkout that handles money is a small data flow. The trust
  boundary matters: everything inside it can see an order, and only the
  processor sees a card.

  Checkout data

               ┌─ external ─┐
               │  Customer  │
               └──────┬─────┘
                      │
                      │
                   Cart ①
                      │
                      │
                      │
                      │
                      │
            ╭─ Our systems ────────╮
            │         ▼            │
            │ ┌─ process ─────┐    │
            │ │ Validate cart │    │
            │ └───────┬───────┘    │
            │         │            │
            │         │            │

            │    │ ╎        │      │

            ╰────┼───────┼─────────╯
                 │       ╎
                 │       ╎
                 │       ╎
          ╭──────╯       ╎
  Charge request ②    Result
          │              ╎
          ▼              ╎
        ┌─ external ─────┴──┐
        │ Payment processor │
        └───────────────────┘

  ① The cart is checked for stock and price before any money moves.
  ② Only a token and an amount leave our systems.
  ③ A paid order is stored last, so no order exists without a charge.
