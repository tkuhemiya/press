
  Diffs
  ━━━━━

  A diagram can show a change. Mark each line that changed with + if it exists
  after the change, or - if it existed before. Unmarked lines are the same on
  both sides. A diff reads like git: there are only additions and removals. A
  graph is drawn as two aligned panels from one layout, Before and After, on
  screen, in images, on paper and in the terminal: removed things red on the
  left, added things green on the right. A table (er, class, tradeoffs,
  dependency) stays one figure, and an edited row is its old version, red and
  struck through, above its new version in green. Labels also start with + or −,
  so a diff still reads in black and white. {role=happy} and {role=error} look
  like ordinary nodes. Every diagram type takes the same marks.

  ## Checkout, after the cache change

  Sessions move from the legacy store to a cache, and the order API is renamed.
  The write goes to a new database, and the refund path is removed with the
  legacy store.

  2. Storefront ╌▶ Shopper: catalogue
  3. Shopper ─▶ Storefront: open checkout
  4. Storefront ─▶ Checkout API: place order
  5. Checkout API ─▶ + Cache: + check stock
  6. Checkout API ─▶ − Old orders table: − write order
  7. Checkout API ─▶ + Orders DB: + write order
  8. Checkout API ╌▶ Storefront: + order placed
  9. Storefront ╌▶ Shopper: + confirmation
  10. Checkout API ─▶ − Old orders table: − refund
  11. − Old orders table ╌▶ Checkout API: − refunded
  12. Checkout API ╌▶ Storefront: error page
